# 技术架构与保证边界

## 为什么是 ReAct

`agent` 把当前请求、已发布知识结构、已见候选、已展开节点、程序核验的证据和剩余预算交给**一个本地语言模型**。模型每次只返回六工具之一及严格参数。`tools` 执行并写入结果，再由 `guard` 决定继续、压缩、暂停或升级。合法工具顺序并不唯一；测试提供器的两个顺序用于验证程序允许重排，不能替代真正模型推理验收。

五个 LangGraph 节点：

| 节点 | 职责 |
|---|---|
| agent | 单次结构化动作提议；调用开始前持久化 |
| tools | 严格参数校验，执行六种有界工具，提交证据和检查点 |
| guard | 身份/知识/数据/模型快照、预算、未知调用、停止条件 |
| compact | 旧观察写入不可变制品，保留近期观察、全部证据身份、预算 |
| escalate | 明确结束为人工升级，不伪造诊断 |

每节点执行前检查快照。初始入口是 guard，而不是自动跑一整串工具。

本地提供器根据已签发状态生成当次可选动作菜单：未分类时只开放分类；之后按展开可见性、未检信号、已回答观察和已有反证收窄选择。选中时序工具时，参数绑定为当前可见未检信号的唯一批次（最多 12 项）；选中提交叶子时，路径和引用绑定到该叶子的真实祖先及已签发证据，不能让模型随意排列 ID。程序没有读取案例标签、预期答案或原始信号来替模型选工具。多个合法动作仍可由模型选择顺序；菜单只是减少无效输出，后端六工具及最终提交独立重验，不信任生成 schema 能完整执行所有限制。

为减少本地 CPU 冷启动输入处理，决策模型上下文省去节点词法检索索引 `terms` 和值为 null 的可选字段；保留标签、实际声明谓词和全部证据。动态菜单、schema 生成和后端校验仍使用完整树，不以输入投影替代执行约束。

## 为什么需要 Heavy Harness

模型只能提出动作，不能自己更改阈值、时间窗、知识版本、测量值或最终诊断状态。

- 工厂授权来自当前数据库身份，不接受模型或请求自报角色。
- 任务只允许原拥有者访问；管理员不是跨拥有者读取捷径。
- 知识树、事件、设备、窗口、数据 hash 和模型 fingerprint 在创建时固定。
- 叶子候选必须由知识工具签发，路径从根连续且祖先已展开。
- 证据绑定 task/actor/plant/device/event/window/tree/data，不能借用其他任务的结果。
- 所有已声明、被树引用的信号条件必须检查且非缺失。选中路径需要全套条件证据，包括 OR 中未支持的条件。
- global_required 与 mandatory 必须支持；叶子 gate 按 AND/OR 计算。
- 其他路径仍可能成立但缺人工条件时，不能假装已排除；多个支持候选必须升级。
- 定义“故障特异信号”为诊断叶子的条件，扣除正常叶子和全局必检条件。若存在选中路径以外的故障特异正证据，拒绝为未解释信号。
- 正常、故障和冲突都是树内规则结果，不是通用安全保证。
- guard 发现已签发的必需信号证据 missing 时，以证据编号为见证立即升级。只有全部引用信号均已检查，才判断是否存在任何仍可能满足的叶子；人工条件保守视为可能，不因尚未回答而排除。若无任何叶子能解释完整信号及全部故障特异正证据，则以 conflicting_signals 停止，而不是依赖模型出错来停止。

意图分类工具是明确标识的本地关键词分类器，不是语言模型，也不承担设备安全保证。候选检索是已发布树上的确定性词法排序，排序分数不是概率或诊断证据。系统没有设备写入工具，所以不能靠文字绕过为 PLC 下发命令。

## 离线知识与真实推理

原创报告包含说明文字和可审计的结构化 YAML 片段。默认从片段确定性抽取草稿，**不冒充从任意自然语言报告自动学会诊断规则**。草稿可通过受控本地提取接口扩展，但其输出仍必须走同样校验/人工审核。

Pydantic 验证 ID、引用、单父树、连通性、条件源和字段类型；OWL/HermiT 检查本体角色、约束一致性、类可满足性与可推导分类。二者不是替代关系。

真正 HermiT 在隔离子进程调用 Java，限制超时和堆内存，不让在线服务随意导入网络本体。推理后的 OWL 重新加载核验，保存输入/输出/引擎 hash 和分类记录。只有真实成功检查的不可变版本才能由管理员显式发布。发布旧版本不修改新旧版本内容，但会变更 active 指针；已有在线任务因此不能悄悄改用新树。

**HermiT 不会证明阈值正确、测量可靠、规则能泛化或现实根因成立。** 数值条件由独立时序工具验证，阈值需要业务及现场验证后才能用于真实场景。

## 时序与人工观察

数据由原创参数化数值模型生成，不直接返回案例标签作为答案。真实计算 mean/max/min/difference_mean；差值需要时间戳一一配对。单位、样本数、质量标志、非有限数、覆盖间隙、末样本时效和窗口范围分别检查。不完整时返回 missing 而不是“正常”。

时窗采用 `[start_ms, end_ms)`。合成夹具使用 30 秒/30 个点，毫秒时间戳不是现实生产时间。

人工问题只能绑定声明为 human 的条件。显示的问题由程序根据已发布的 label、human_key 和阈值生成，模型拟写的问题仅保存为不可信审计字段，不决定回答语义。用户必须主动选择原始观察事实的 true/false，不是回答“是否符合诊断”；包括 threshold=false 的条件也按原始布尔值比较。回答前复核完整条件及知识版本，Evidence 保留问题正文、条件、question/actor/note，并明确是人工声明而非传感器证明。不得用人工工具补造缺失的 signal 证据；相同事件人工观察冻结，需更正应建立新任务。

## 持久化与调用不确定性

SQLite 单机存储、WAL、短事务。内容寻址 JSON 制品通过临时文件写入、fsync、无覆盖硬链接原子发布，最终 hash 验证；崩溃可能留下未引用制品，不能把文件存在当业务已提交。

模型调用前持久化 started；有效结果记录 response/tokens 后才成为 pending action。工具结果、Evidence 引用及检查点同事务。进程死亡可能留下 started，恢复必须作为未知处理，不自动调用模型第二次。

只有任务拥有者且为管理员才可对账，声明“没有可用结果”或补录完整动作及使用量。没有结果不等于零消耗：已知失败响应的 usage 也计入预算；未知用量可由管理员核实后填写（包括有依据的零），若未填写则保守占用剩余 token 预算。已记录用量不可下调、重复对账不重复计费。此记录是**人工核查声明，不是密码学外部回执**。取消不证明在途模型未执行。

版本/CAS 与租约阻止旧 worker 覆盖新 worker。图内累计时间、calls/tools/tokens 在恢复和压缩后不清零；每任务冻结预算。当前默认 20 次模型、32 次工具、64,000 total tokens、300 秒图内合作式累计时间。64,000 包含反复发送的输入上下文，不是只算输出。

300 秒不是 OS 硬终止上限；在单次调用结束后可能超出才阻断后续工具。未知中断节点按持久化开始时间保守计费，停机时间也可能计入。独立报告不占原诊断图预算，但单次模型仍有提供器超时/长度限制。

## 报告与措施执行隔离

submitted 后冻结诊断。报告服务只读其引用；确定性 authoritative 区包含真实已记录的结论和全部证据，模型说明放入 untrusted/unreviewed 草稿。为了减少本地 CPU 重复输入，语言模型只收到范围信息一次、冻结结论/引用和全部证据的结果投影，省去重复 scope 和审计元数据，不省略反证/缺失结果；正式报告仍保存完整原始 authoritative 区。模型即使声称“已维修”也不会生成执行记录。生成失败/未知单独记账；相同 action 不自动重试。人工审签绑定精确 content_hash，不能静默替换。

本工程不实现设备控制或维修执行接口。报告审签通过也不代表措施已执行、异常已解除或收益已确认。

## 适用范围

本地单机 Demo／测试版，用于生产部署前的本地验证，不是多节点调度、高并发 SaaS 或安全认证系统。可信本地主机管理员可读写数据目录；hash 不防拥有全部文件和数据库写权限的恶意管理员。原始投诉、知识和工具文本是不可信数据，提示约束不代替程序执行边界。
